# 一套语音视频聊天的设计方案
主要以 Centrifugo + LiveKit 为基础去实现的方案

## 🔁完整交互流程（以群组语音为例）
### 1️⃣ 加入群组 & 订阅信令频道
- 用户登录后，客户端通过业务后端鉴权，获取 Centrifugo 连接 Token。
- 客户端连接 Centrifugo，订阅自己的个人频道（如 user:{uid}），用于接收所有呼叫、群组邀请、上麦通知等信令。
- 同时，客户端可能还会订阅群组信息频道（可选），用于接收群内公告或状态变化（如谁上麦了）。

### 2️⃣ 用户上麦（发布音频）

- 用户点击“上麦”按钮：
1. 客户端调用业务后端接口，请求在 LiveKit 中发布音频。 
2. 业务后端验证权限后，调用 LiveKit API 获取该用户加入当前语音房间的 Token（若房间不存在则创建）。 
3. 业务后端将 Token 返回给客户端。 
4. 客户端使用 Token 连接 LiveKit 房间，并发布本地麦克风音频轨道。 
5. LiveKit 自动将该音频流转发给房间内所有其他参与者。 
6. 业务后端可选地通过 Centrifugo 向群组内所有用户广播“某人上麦了”的状态信令（用于 UI 展示）。

注意：上麦不需要通过 Centrifugo 发送媒体信令，因为媒体信令（SDP/ICE）直接由客户端与 LiveKit 交互。

### 3️⃣ 听众收听
- 房间内的其他用户（包括未上麦的观众）自动订阅所有已上麦用户的音频轨道。

- 他们不需要额外操作，LiveKit 会自动将多路音频流推送到每个客户端，客户端本地混音后播放。

### 4️⃣ 用户下麦
- 用户点击“下麦”： 
1. 客户端调用业务后端接口。 
2. 业务后端通知客户端停止发布音频（或直接通过 LiveKit SDK 的 unpublish 方法）。 
3. 客户端停止发布，LiveKit 自动通知其他订阅者移除该音频流。 
4. 业务后端可广播“某人下麦了”的信令。

### 5️⃣ 发起一对一呼叫（可选）
- 对于私聊语音，流程类似，但信令通过 Centrifugo 在双方的个人频道之间传递： 
1. A 呼叫 B → 业务后端创建 LiveKit 房间，获取双方的 Token。 
2. 业务后端通过 Centrifugo 向 user:B 发送呼叫信令（含房间信息）。 
3. B 应答 → 业务后端向 user:A 发送应答信令。 
4. A、B 分别连接 LiveKit 房间，开始媒体传输。

### 6️⃣ 挂断 / 退出群组
- 用户挂断或退出群组时：

1. 客户端通知业务后端。 
2. 业务后端让该用户离开 LiveKit 房间（调用 LiveKit API）。 
3. 业务后端通过 Centrifugo 向相关方发送挂断或退出信令。
