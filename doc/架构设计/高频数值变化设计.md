# 高频数值变化设计

将某个时间范围内的数值进行聚合，再写入 mysql 

# 前提 
某功能需要高频变更数值，若每次直接写入 mysql ，会导致数据量过大，导致 mysql 性能下降, 服务也没有办法消费掉，并且若是进度数据则存在大量锁冲突。

例如：
100个不同用户向用户A点击送礼，触发100次送礼消息，每条消息都会产生对用户A的魅力值增加。

### 设计思路

每n秒内产生的所有的增减数值都写入到 redis 中，延时任务触发将redis中的数据写入 mysql 

#### 具体实现
假设我需要将1秒内的数据聚合写入 mysql , 聚合函数为 函数 `Agg(aggId, key, timeArea, score)`
`aggId` 业务id
`key` 自定义追加内容
`timeArea` 时间范围
`score` 数值

1. 用户点击送礼，触发收礼人经验值变更，调用 redis指令 `RPUSH agg:value:业务id:自定义追加内容 变更数值` （`RPUSH agg:value:1:10001 100`）
2. 执行成功 `RPUSH`后构建延时队列任务，
   - 根据`timeArea`去计算出分割出节点时间戳
     - 当 timeArea=1 时候，那么无需处理
     - 当 timeArea>1 时，需要以整点为单位按照 `timeArea` 进行分割时间块, 获取当前时间块对应的时间戳
   - 延时任务key为 `agg:delay:业务id:自定义追加内容:当前时间块的时间戳` （`agg:delay:1:10001:1780000000`）
   - 执行时间为当前时间戳+`timeArea`秒（1780000001）
3. 延时队列触发，延时任务携带的数据 Task{AggKey: `agg:value:业务id:自定义追加内容`, Timestamp: 1780000000 }
   - newKey := Task.AggKey + ":snapshot" + Task.1780000000
   - 执行 redis指令 `RENAME Task.AggKey newKey`
     - 若失败则，证明目前没有需要聚合的数据
   - 执行 redis指令 `LLEN newKey`
     - 若小于等于 1000， 执行 redis指令 `LPOP newKey` 1000
     - 若大于 1000， 使用 pipeline 执行 redis指令 `LPOP newKey` 1000，直至全部获取完毕
4. 聚合结果写入 mysql
5. 执行 redis指令 `DEL newKey` 删除该临时key



### 时间块代码实现
```go
package main

import (
	"time"
)

// GetBlockTimeWithAnchor 按照自然日零点作为原点进行切片
// timeArea: 切片步长（秒）
// nowTime: 当前请求的时间
func GetBlockTimeWithAnchor(timeArea int64, nowTime time.Time) int64 {
	if timeArea <= 0 {
		return nowTime.Unix()
	}

	// 1. 获取当前时间所在时区的“今天零点”
	year, month, day := nowTime.Date()
	zeroTime := time.Date(year, month, day, 0, 0, 0, 0, nowTime.Location())
	zeroTimestamp := zeroTime.Unix()

	// 2. 计算当前时间距离今天零点的相对秒数
	currentTimestamp := nowTime.Unix()
	relativeSeconds := currentTimestamp - zeroTimestamp

	// 3. 在相对秒数内进行分块计算
	blockRelativeSeconds := (relativeSeconds / timeArea) * timeArea

	// 4. 加上零点基准，还原为绝对 Unix 时间戳
	return zeroTimestamp + blockRelativeSeconds
}

```
