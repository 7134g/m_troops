## 任务引擎

### 需求

想要实现用于活动的任务系统

1. 通过活动id创建多个任务
2. 任务类型
    - 唯一性任务
    - 无时间限制任务
    - 日任务
    - 周任务
    - 月
    - 循环任务
      - 循环条件
      - 循环间隔
      - 循环次数
    - 定时任务
3. 任务完成方式
   - 累计（也就是 + ）
   - 一次性满足（也就是 >= ）
4. 任务直接运行嵌套，如完成多个小任务后，大任务才完成
5. 任务完成奖励

### 方案 1

规则引擎

1. 后台创建任务源
   - 设置活动id和父任务id，若无父任务id，则传0
   - 设置任务类型
   - 是否需要添加子任务
   - 设置任务完成方式：

2. 用户行为触发事件
   - 读取当前活动列表中是否存在该行为任务源
   - 判断是否处于活动时间内
   - 无任务则给该用户创建任务
   - 存在则判断任务类型，根据不同任务类型进行不同处理
     - 定时任务，需要判断是否在任务开始时间内

3. 任务执行
   - 解析任务完成方式，去增减任务进度

4. 任务完成
    - 若是循环任务，则需要置零或者根据上一次进度剩余，再次开始任务
    - 若存在父任务，则判断父任务是否完成，完成则标记为完成任务，发放父任务奖励
    - 其余则标记为完成任务，发放奖励

##### 例子
活动id=1
1. 累计消费金额达到10000，完成任务。 
   后台任务源创建：无时间限制任务，父任务id=0，活动id=1，无子任务，任务完成方式为累计，累计目标为10000。
2. 一次消费金额达到1000，完成任务，运行循环完成。
   后台任务源创建：无时间限制任务，父任务id=0，活动id=1，无子任务，任务完成方式为一次性满足，大于等于目标为1000。
3. 当日连续10次消费金额超过100，完成任务。
   后台任务源创建：当日，父任务id=0，活动id=1，有子任务，任务完成方式为累计，累计目标为3。
     - 父任务id为10001
     - 子任务创建：当日，父任务id=10001，活动id=1，无子任务，任务完成方式为一次性满足，大于等于目标为100。
4. 当周连续5次消费金额超过1000，完成任务。
   后台任务源创建：当周，父任务id=0，活动id=1，有子任务，任务完成方式为累计，累计目标为5。
    - 父任务id为10002
    - 子任务创建：当周，父任务id=10002，活动id=1，无子任务，任务完成方式为一次性满足，大于等于目标为1000。
5. 当消费累计1000和充值累计100同时完成，完成任务。
   后台任务源创建：无时间限制任务，父任务id=0，活动id=1，有子任务，任务完成方式为累计，累计目标为2。
    - 父任务id为10003
    - 子任务创建：无时间限制任务，父任务id=10003，活动id=1，无子任务，任务完成方式为一次性满足，累计目标为1000。
    - 子任务创建：无时间限制任务，父任务id=10003，活动id=1，无子任务，任务完成方式为一次性满足，累计目标为100。

#### 表设计
（mysql）
活动表
id，用户事件类型（数组），活动开始时间，活动结束时间



任务表
id， 父任务id， 任务类型，任务完成方式，任务目标


对应的缓存设计：
    activity:v1:list  -> [{},{},{}...]   获取活动列表
    activity:v1:user:{userId} -> [{},{},{}...]  获取用户进行中的任务列表
