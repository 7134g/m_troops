## 排行榜设计


### 需要解决的问题

1. 同分，不同时间要根据时间先后顺序排序
2. 依赖多个值进行排序。如先排A，如果A分一样，再排B，B分一样，再排C，C分一样，再排D

### 方案 1

只查一次
redis zset（+-16为长度可保证精度，double）

1. redis zset 结构 key 为排行榜名称，value为用户ID，score为用户分数
2. 用户分数组合：100000000000000（15位）基础长度 -》 分数 + 时间戳（9位，当前时间戳-1000000000） 
  - 基础长度：作为 score 的最大值长度，分数和时间戳的值都落在这上 
  - 分数：按照权重分割假如，ABCD最大值都是100，那么该分数组合逻辑为 (D+C*1000+B*1000000+A*1000000000)*1000000000 +9位时间戳
    - 如： A：20，B：30，C：40，D：100，9位时间戳=123456789，那么分数为 20030040100123456789
3. 若同分时间戳也相等，则通过按照field排序去做，field遵循askii码排序，也就是同位数的纯数字id，越小越前


#### 优缺点
计算量高一点，网络io开支小



### 方案 2

查两次redis，一个zset放 userID 和 分数， 另一个放时间戳

1. 写入时候，先zadd写入分数zset，再zset写入时间戳zset
2. 读取时候，先读取分数zset，若存在相同分数的再去读时间戳zset

#### 优缺点
网络io开支大一点，计算量小一点，有概率存在时间戳不正确（同时写入同一个field两条分数时候，时间戳有概率是写入旧时间）


### 方案 3

内存方案，多机器相同排行榜
方案：P2P 实时广播 + SeqID 版本仲裁  + kafka + redis + mysql 最终一致性

consul: 是用于服务发现, 拿来找game服务的
SeqID 版本: 用于标记这一条记录时间，所以每一个用户有自己的SeqID

假设game服有三个game1，game2，game3
1. 客户端请求增加分数，通过网关分配来到game1
2. game1 校验后，生成SeqID 版本，首先将这条用户ID，分数，SeqID 版本变更异步写入kafka
3. game1在写入kafka完成后，更新自身内存中维护的榜单分数和SeqID 版本（需要大于内存中SeqID才更新榜单）
4. game1完成上述步骤后，通过consul找到game2，game3, 异步发起 grpc 将用户ID，分数，SeqID 版本通知给 game2，game3 
5. game2，game3收到game1通知后，更新他们自己内存中的榜单分数和SeqID 版本（需要大于内存中SeqID才更新榜单）
6. 最后，kafka消费线程消费步骤2的消息，写入mysql，再写redis

通过上述方式就完成了多服务榜单一致性问题

启动game服流程
1. 通过consul获取是否存在game服
2. 若存在则，取所有game服中最大的SeqID 版本，然后加载数据到内存
3. 若不存在任何一个game服，那么从redis查出来，加载到内存中
4. 启动定时对账功能，每隔5秒，对齐一下每个game服内存中的值（根据SeqID，选max）
